## 1. CLI Daemon Discovery Mechanism

**Decision**: Fixed default port (8080) with configuration override

**Rationale**:
- Simplest approach for v1
- No additional discovery protocol needed
- Configuration can be passed at space creation or via environment variable

**Implementation**:
- Default port: 8080
- Override via `AgentConfig.daemonPort`
- Future: Add mDNS or config file discovery

**Location in Code**:
- `packages/core/src/runtime/agent/agent-registry.ts:22` - `daemonPort: number`
- `packages/core/src/runtime/agent/cli-daemon-client.ts:14` - Default port logic

## 2. Agent Capability Schema

**Schema**:
```typescript

  tools: string[];        // Available tool names
  inputTypes: string[];   // Supported input types (e.g., "code", "text", "image")
```

- Can add fields later without breaking changes

## 3. Thread Pagination Strategy

**Decision**: Offset-based with configurable limit (default: 50 messages)

**Rationale**:
- Simpler than cursor-based for initial implementation
- Sufficient for typical thread sizes (< 1000 messages)
- Can migrate to cursor-based if performance issues arise

**Implementation**:
- Initial load: 50 most recent messages
- "Load more" button loads next 50
- No automatic pagination (manual trigger)

**Future Considerations**:
- Virtualized scrolling for large threads
- Cursor-based for real-time sync

**Location in Code**:
- Not yet implemented (marked as TODO in `MultiParticipantMessageRepository`)

## 4. Security Token Implementation

**Decision**: HMAC-SHA256 with shared secret

**Rationale**:
- Simpler than JWT (no token expiry, no key rotation needed for v1)
- Sufficient for localhost daemon authentication
- Can upgrade to JWT in v2

**Implementation**:
- Token generated by space admin UI
- Stored in `AgentConfig.authToken`
- Passed as `Authorization: Bearer <token>` header
- Daemon validates against configured secret

**Security Considerations**:
- Token should be long (32+ bytes)
- Stored securely (not in localStorage)
- HTTPS required for non-localhost deployments

**Location in Code**:
- `packages/core/src/runtime/agent/agent-registry.ts:24` - `authToken?: string`
- `packages/core/src/runtime/agent/cli-daemon-client.ts:15` - Token usage

## 5. Rate Limiting Implementation

**Decision**: In-memory per-thread limiter

**Rationale**:
- No external dependencies (Redis)
- Sufficient for single-instance deployments
- Simple to implement and reason about

**Implementation**:
- `AgentOrchestrator` tracks timestamps per thread
- Max 3 invocations per minute per thread
- Oldest timestamps expire after 60 seconds

**Limitations**:
- Not shared across server instances
- Resets on server restart

**Future Extensions**:
- Redis-backed rate limiter for multi-instance
- Per-participant limits
- Global rate limits

**Location in Code**:
- `packages/core/src/runtime/agent/agent-orchestrator.ts:123-137`
